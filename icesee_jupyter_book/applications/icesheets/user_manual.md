## Application Overview

CryoLauncher is the numerical-modeling application within CryoStack. It provides a browser-based interface for discovering, configuring, and running supported ice-sheet models across local, remote, HPC, and cloud computing environments.

This manual focuses on the controls and behavior of the application. For a short first simulation, begin with the [Getting Started guide](getting_started).

## User Modes

### Basic Mode

Basic Mode is intended for standard examples and users who want CryoLauncher to discover the required workflow information automatically.

It may automatically identify:

- installed models,
- available examples,
- model directories,
- configuration files,
- and execution targets.

Basic Mode is appropriate for tutorials, demonstrations, and standard model examples.

### Advanced Mode

Advanced Mode exposes additional configuration controls for custom research workflows.

Use Advanced Mode when you need to:

- enter custom model or example directories,
- modify input files,
- change the run target,
- customize execution commands,
- select a nonstandard environment,
- or control backend settings manually.

## Model and Example Selection

### Model

The **Model** menu lists the scientific models available on the selected execution backend.

CryoLauncher currently supports:

- **ISSM**
- **Icepack**

The available choices depend on the software environments installed or configured on the selected system.

### Examples

The **Examples** menu displays discovered workflows for the selected model.

The details panel may report:

- model name,
- example label,
- category,
- filesystem path,
- entry point,
- and a short description.

### Files

The **Files** control identifies source, configuration, or input files associated with the selected example.

### Run Target

The **Run target** identifies the file or command used to begin execution.

Examples may include:

```text
runme.m
run.py
example.py
```

## Supported Models

### ISSM

The Ice-sheet and Sea-level System Model is a multiphysics framework for ice-sheet, glacier, and sea-level simulations.

For ISSM workflows, CryoLauncher may expose:

- MATLAB model files,
- example directories,
- model configuration,
- execution targets,
- and remote or scheduler settings.

### Icepack

Icepack is a Python library built on Firedrake for glacier and ice-sheet modeling.

For Icepack workflows, CryoLauncher may expose:

- Python entry points,
- example directories,
- Firedrake environments,
- configuration files,
- and generated output products.

## Editable Configuration

The editable-configuration panel allows supported source or configuration files to be inspected and modified before submission.

Changes made here may directly affect:

- model geometry,
- physical parameters,
- numerical settings,
- output behavior,
- and execution commands.

Users should review modifications carefully before launching a workflow.

## Remote Connection

The remote-connection section contains the information CryoLauncher needs to reach another computing system.

Typical fields include:

- hostname,
- username,
- SSH port,
- remote directory,
- connection method,
- and connector session.

The remote execution directory must be accessible to the user account running the simulation.

## Authentication

Authentication options depend on the selected backend and deployment.

CryoLauncher may use:

- SSH keys,
- password-based authentication,
- server-side credentials,
- connector-mediated access,
- or institutional authentication.

Sensitive credentials should never be written into model source files.

## Server-Side SSH Key Manager

The key manager supports SSH connections initiated from the CryoStack host.

Depending on user permissions, it may allow users to:

- generate an SSH key,
- register a public key,
- select an existing key,
- test remote access,
- and remove an unused key.

Private keys must remain protected.

## Execution Backend

The execution-backend panel defines how the selected command is launched on the remote system.

Backend configuration may specify:

- environment activation,
- executable paths,
- MPI launch commands,
- container commands,
- scheduler submission,
- and custom environment variables.

## Slurm Resources

When a Slurm-managed system is selected, CryoLauncher may expose:

| Setting | Purpose |
|---|---|
| Account | Project or allocation charged by the scheduler |
| Partition | Scheduler queue used for the job |
| Nodes | Number of requested compute nodes |
| Tasks | Number of parallel tasks |
| CPUs per task | CPU resources assigned to each task |
| Memory | Requested memory |
| Wall time | Maximum job duration |
| Job name | Name displayed by the scheduler |

Requested values must comply with the policies and limits of the selected cluster.

## CryoStack Connector

The CryoStack Connector enables access to systems that cannot be reached directly from the CryoStack server.

A typical connector workflow is:

1. Launch the connector on the user’s computer.
2. Establish a connector session.
3. Confirm that the session is online.
4. Configure the target system in CryoLauncher.
5. Submit the workflow.
6. Monitor execution from the browser.
7. Retrieve or inspect the generated outputs.

The current session identifier and online status are shown in the Run Log.

## Submitting a Workflow

Before submission, verify:

- the selected user mode,
- execution mode,
- model and example,
- discovered files,
- run target,
- authentication,
- remote directory,
- and scheduler resources.

CryoLauncher then prepares the required files and commands for the selected backend.

## Monitoring Execution

The Run Log may display:

- connector activity,
- staging operations,
- environment activation,
- submission commands,
- job identifiers,
- standard output,
- standard error,
- warnings,
- failures,
- and output locations.

A scheduler-managed job may continue running after the browser is closed, provided submission completed successfully.

## Results Preview

The Results Preview panel may display:

- figures,
- HTML reports,
- diagnostic summaries,
- model output files,
- logs,
- downloadable archives,
- and links to execution directories.

Not every model example produces a browser preview. The available results depend on the workflow.

## Output Locations

Outputs may be written to:

- the CryoStack server,
- a remote working directory,
- an HPC filesystem,
- cloud storage,
- or a downloadable archive.

The final location should be reported in the Run Log.

## Security Guidance

Users should:

- protect private SSH keys,
- avoid placing passwords in source files,
- use approved institutional authentication,
- review custom commands before execution,
- and access only systems for which they are authorized.
