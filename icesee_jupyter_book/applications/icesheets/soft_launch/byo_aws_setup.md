# Connect an AWS account

Follow the first-time steps and recording below to create the AWS access stack,
read its **RoleArn** output and verify the connection in CryoLauncher. If your
account already shows **Connected**, use the existing-connection review below.
The connected account pays AWS charges; a Resource Allocations balance does
not automatically fund that account.

## First-time connection

Use these steps for an AWS account that is not yet connected in CryoLauncher.
If your account already shows **Connected**, use the existing-connection review
below. Use an AWS account where you are authorized to create the access stack.

1. In CryoLauncher, choose **Cloud**, then under **Cloud access** choose **Bring your own AWS (BYO)**.
2. Open **AWS Account**, then choose **Connect AWS Account**.
3. Choose the blue **Open AWS Setup** button. It opens AWS CloudFormation's **Quick create stack** page in a **new browser tab**. Keep the CryoLauncher tab open. If AWS asks you to sign in, sign in to the account you intend to connect and return to the Quick Create page.
4. Review the supplied template and prefilled connection parameters. After reviewing the permissions, select the required **IAM acknowledgement**, then choose **Create stack**.
5. Wait for the stack status to become **CREATE_COMPLETE**. A stack that is still creating is not ready for the next step.
6. Open the stack's **Outputs** tab.
7. Find **RoleArn**, then select and copy the full ARN in the **Value** column (**Ctrl+C** or **Command+C**). Copy the ARN value, rather than the output key or stack ID.
8. Return to the CryoLauncher tab, paste that value into **Role ARN**, then choose **Verify connection**.
9. Wait for verification to succeed and confirm that **AWS Account** shows **Connected**.

**Basic** uses Fargate; **Advanced → Compute** offers Fargate and EC2 before **Prepare cloud**.

Signing in to CryoStack or AWS is separate from creating the access stack and
verifying the connection. These connection steps do not launch a model. Prepare
and review the scientific run separately, then explicitly launch it from
**Review & Launch** when ready.

role solely to follow this review. Keep account/role identifiers private.
