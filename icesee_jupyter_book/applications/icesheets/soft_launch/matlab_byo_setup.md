# MATLAB BYO setup for ISSM

This tutorial configures MATLAB licensing for ISSM on an existing approved
**BYO AWS** connection. Icepack needs no MATLAB license. The container supplies
the runtime, but your institution supplies the license service; the public
tutorial uses the format `port@server`, never the actual institutional value.
For example, `27000@license.example.edu` illustrates the syntax. It is not a
working endpoint. Use the exact private value supplied by your institution.

The corresponding setup clip is separate from the science clips in the
[recording matrix](recording_matrix.md). It must explain each branch below,
mask entered values and secret references, and identify an existing-secret
reattachment honestly. The new recording is not accepted until reviewed.

## Recorded existing-license walkthrough

The **195-second** video demonstrates reattaching the existing managed license,
same-owner Connector readiness and actual subsequent native MATLAB/ISSM
execution. It does not create a new secret or overwrite its value. The
conditional reference-reset steps, external Connector code entry and VPN setup
are explained rather than filmed; the complete written procedure below covers
the applicable steps. Readiness and Connector status alone are not checkout.

## Select the account and license configuration

1. Sign in to [CryoLauncher](https://cryostack.eas.gatech.edu/cryolauncher/),
   complete account approval, and select **Cloud → ISSM**. Confirm the approved
   BYO AWS connection and Region. A pilot allowance does not fund a BYO account
   automatically; use the route recorded in your invitation.
2. Open **Cloud Environment → MATLAB LICENSE**. A raw `port@server` license
   value belongs in the masked **MATLAB license** field. An AWS Secrets Manager
   ARN is a reference to a saved secret and belongs in **Existing secret ARN**;
   these are different inputs.
3. **First configuration with no existing managed secret:** enter the private
   value in **MATLAB license**, then select **Configure license**. CryoStack
   creates its fixed-name secret in the connected AWS account and Region. On
   success the raw input clears and the form becomes **MATLAB license
   configured**. The saved CryoStack configuration retains the secret ARN,
   not the raw license value.
4. **An existing managed secret:** the same **Configure license** operation
   recovers its ARN from secret metadata and reattaches it. It does **not**
   overwrite the existing value with newly typed text. The configured view has
   no managed-secret **Reconfigure** button; update an actual endpoint value
   through AWS Secrets Manager when required, then reuse the reference.
5. **An existing secret reference:** open **Advanced license configuration →
   Use an existing AWS Secrets Manager secret**, enter the matching **Existing
   secret ARN**, and select **Use existing secret**. This attaches a reference;
   it does not accept a license value or copy a secret from another account.
   Keep the connected account/Region and secret scope consistent.

For a recording of reattachment, privately retain the current ARN for recovery.
Clearing **Existing secret ARN** and choosing **Use existing secret** with a
blank field clears the local reference; it does not delete or modify the AWS
secret. The masked form can then be shown again. **Configure license** recovers
an existing fixed-name secret and reattaches it. Caption this as **existing
configured license reattached**, not a newly saved endpoint or a secret-value
rotation. Restore the retained reference if recovery fails. Do not clear a
working reference merely to claim that an unchanged value was newly created.

## Attach access to the ISSM execution resource

Configuration attempts to attach secret access to the existing ECS execution
role. This is an IAM permission/reference step, not a license purchase. If the
execution resource is not prepared, follow the displayed **Run Prepare cloud**
instruction and the organizer's approved resource-preparation sequence. Wait
for Account **Connected** and Storage, Containers and Compute **Ready**.

A secret in a different AWS account or Region is not automatically usable.
The owner's working BYO account and secret do not transfer into a sponsor
funding account merely by displaying a pilot credit balance.

## Connect from the institutional network

If the license service requires the campus network or VPN:

1. Use a computer that can reach that service. Connect its institutional VPN
   first when needed, and keep the network/VPN available throughout the run.
2. In **INSTITUTIONAL CONNECTION**, select **Open Connector...**. Install the
   [Connector for your operating system](https://cryostack.eas.gatech.edu/downloads/connectors/)
   if necessary, then pair it using the displayed pairing flow. This is the
   same owner-bound paired session used by Remote; reuse a working session.
3. Keep the Connector running. Select **Re-check** and confirm its connected
   state under the same signed-in CryoStack identity. **Disconnect** ends that
   connection and can interrupt runs that need it; do not use it during a run.

A Connector paired to another CryoStack user is not your connection. The
separate hosted-ISSM candidate also requires each participant's configured
license reference and same-owner live Connector; the operator's existing
pairing does not qualify a fresh invitee automatically. Its production status
remains in the [pilot release checks](pilot_readiness.md).

## Check readiness, then verify actual licensing in the run

Before launch, confirm **MATLAB license configured**, the required Connector
online, and **ISSM runtime: Ready** in **Review & Launch**. Also check the model,
image, resource shape, timeout and cost estimate. **Re-check** verifies the
paired connection; the AWS **Test connection** control checks AWS access.
Neither performs a MATLAB license checkout. There is no separate pre-launch
MATLAB checkout button in the current interface.

Use the reviewed [Basic ISSM](basic_issm.md) run for the actual MATLAB/ISSM
execution check. Keep the Connector/VPN active, inspect the completion log and
native `StressbalanceSolution` / `Vel` result, then save and open the results
archive. A successful setup badge alone is not proof of license checkout or
solver completion. Record any failure and its correction without exposing the
license value, ARN, pairing code, account identifiers or private network details.
