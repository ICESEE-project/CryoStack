# Basic ISSM: first AWS run

This walkthrough runs SquareIceShelf in SSA Stressbalance through the existing BYO AWS connection. It reuses the configured MATLAB license and the Connector tunnel required by that institutional license. Hosted ISSM licensing is a separate release check; it is not established by this BYO run.

## Before you start

Complete [Before your first run](../soft_launch.md) (account, approval, AWS connection, MATLAB license). Sign in to [CryoLauncher](https://cryostack.eas.gatech.edu/cryolauncher/). Use only the account and funding arrangement confirmed in your invitation. A connected AWS account is not proof of a project-funded allocation. Do not create a personal AWS account or enter payment details for this pilot unless the organizer explicitly requests that route.

Keep the case and container selected in the reviewed run plan, and run one job at a time. Record the image, resource shape and timeout before launch. Queueing and image startup add to model execution time. A displayed 60-minute time limit is a ceiling, not an observation that this example takes 60 minutes.

## Steps

1. Select **Cloud**, **Basic**, and **ISSM**.
2. Choose **SquareIceShelf**. Confirm the Details panel names the expected model and example.
3. In **Cloud Environment**, verify the AWS connection approved for this BYO tutorial. If your invitation specifies hosted project funding, contact the organizer rather than substituting your own paid account.
4. Follow [MATLAB BYO setup](matlab_byo_setup.md) and reuse the existing configuration. Check **MATLAB license configured** and the same-owner paired Connector. **Configure license** can recover an existing managed secret reference; it does not overwrite that secret with newly typed text. Actual endpoint changes use AWS Secrets Manager. Keep the value and ARN out of scripts and recordings.
5. Check Account, Storage, Containers and Compute. If Account shows **Connected** and the other three show **Ready**, continue. Otherwise follow the organizer's preparation instructions before using **Prepare cloud**.
6. Leave scientific parameters at their defaults for this first case. Open **Review & Launch**. Check the model, image, region, resource shape, and time limit. If the cost estimate is unavailable, ask the organizer before participant runs.
7. Click **Launch cloud run** once. Watch **Queued → Running → Completed**. Queued and Starting may take longer than the calculation.
8. Open **View log**, then **View results**. Select **StressbalanceSolution** and **Vel**, then render the velocity field.
9. Click **Download results**, then the generated download link, and open the archive locally. Check it contains outputs rather than an empty directory.

## Continue with model initialization

Follow [uploading a dataset](upload_dataset.md) for the bounded synthetic ISSM shelf. Keep the small case until its license, solve, result retrieval and download have all passed.

## Expected outcome and evidence

A successful submission has a job ID. A successful model run finishes without a solver error. A complete tutorial also has retrievable logs, nonempty results, a readable figure, and a downloaded archive. Record all of these; a green job status alone is insufficient.
