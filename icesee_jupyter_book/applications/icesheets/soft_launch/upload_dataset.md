# Upload a dataset and initialize a model

Datasets stores an uploaded file and stages its referenced bytes under `data/`; it does not convert the format or choose a scientific loader. The browser upload limit is 50 MiB per file. The existing launch packet contains synthetic JSON inputs. A separate prepared recording case below uses a bounded ZIP/NetCDF field; its native runs are not yet accepted. Files such as `.mat`, `.nc`, `.h5`, `.csv`, `.txt`, `.dat`, `.exp`, `.tif` and `.zip` need a reader in your saved script and its dependencies in the selected execution image.

## Bring your own format

Upload the file, reference it in an example you own, then read `data/<filename>` in your saved script. The following reader calls illustrate file APIs; they are not evidence that every library or file variant has passed an AWS model run.

| Format | ISSM (MATLAB) | Icepack (Python) |
| --- | --- | --- |
| `.mat` | `S = load('data/obs.mat');` | `scipy.io.loadmat('data/obs.mat')`; use `h5py` for v7.3 files |
| `.nc` | `ncread('data/obs.nc', 'thickness')` | `xarray.open_dataset('data/obs.nc')` |
| `.h5` | `h5read('data/obs.h5', '/thickness')` | `h5py.File('data/obs.h5', 'r')` |
| `.csv` | `readtable('data/obs.csv')` | `numpy.genfromtxt('data/obs.csv', delimiter=',', names=True)` |
| `.zip` | `unzip('data/inputs.zip', 'data');` | `zipfile.ZipFile('data/inputs.zip').extractall('data')` |

Notes that apply to every format:

- **One dataset is one file.** To bring a folder, zip it, upload the zip, and extract it at the top of your script as shown above.
- **Archives are not unpacked for you.** A `.zip` arrives in `data/` as a `.zip`.
- **The browser limit is 50 MiB per file.** Split or subset larger data before uploading.
- **Nothing is inferred from the file.** Uploading and referencing make the file available; they do not choose a model or initialize it.
- **Text formats can be opened in the Editor.** Binary formats are listed as `data` and cannot be edited there.

## Steps

1. Complete the matching Basic tutorial, then select **Advanced**. Create a user example and install the supplied model files as described in the Advanced tutorial.
2. In **Datasets**, choose the matching input with **Choose data files**, then click the separate **Upload** button. Check the upload outcome and dataset list; selecting a file alone does not store it. Use this control for the model input data, not the editor's **Choose script files**.
3. Confirm the filename and nonzero size appear in the dataset list. The browser limit is 50 MiB per file. The supplied Icepack validator additionally rejects JSON inputs over 2 MiB; the supplied ISSM loader has no separate size check.
4. Select the saved file, then **Reference in example**. Leave “reference as” blank to stage it as `data/<filename>`. Read the exact staged path in the feedback and use that path in the script; do not add `data/` twice or use an absolute PC path. If the selected example is a read-only application example, clone it to **My Workspace** first; referencing is disabled until you select an example you own.
5. Open the script in **Editor**. Confirm it loads `data/issm-shelf-small-v1.json` or `data/icepack-shelf-small-v1.json`. With your own data, this is where you replace the loader with the reader for your format from the table above.
6. Save, prepare cloud, review and launch. The supplied loader checks model, units, dimensions, finite values, thickness, mesh bounds, and supported step count before allocating the mesh.
7. Verify a native model solve, step log, figure, and `outputs/reference-metrics.json`. Download results.
