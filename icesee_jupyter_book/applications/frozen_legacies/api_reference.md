This page documents the **internal application API** used by the Frozen Legacies browser modules. It is developer documentation, not a stable public interface: endpoints may change with the application. Integrations that need a stable contract should use the downloadable products and dataset files instead. The automatic-picking endpoints are implemented and tested, and URSA has been run end to end on the F127 reference strip in a separate environment; its results remain scientifically unvalidated (see the Developer Guide).

## Conventions

- **Base path:** `/frozen-legacies/api/`.
- **Authentication:** every endpoint requires a CryoStack session (the `icesee_session` cookie set at sign-in). Without one the response is `401 {"error": "Authentication required."}`. The application page and its files (`/frozen-legacies/`, `/frozen-legacies/assets/`, `/frozen-legacies/data/`) redirect anonymous requests to `/auth/login?return_to=…` instead.
- **Ownership:** asset routes act only on assets in the signed-in user's workspace. Another user's asset, a missing asset, and a malformed ID all answer `404 {"error": "Radar asset not found."}`.
- **Identifiers:** `<asset_id>` is 32 lowercase hex characters generated by the server; `<product_id>` matches `[a-z0-9][a-z0-9-]{0,63}`; shared source keys match `[a-z0-9][a-z0-9._-]{0,63}`. No endpoint accepts a filesystem path.
- **State-changing requests** (`POST`, `DELETE`) with an `Origin` header from another site answer `403`.
- **Errors** are JSON: `{"error": "<message>"}`. `400` invalid request or rejected file; `404` not found / not owned; `409` conflict (stale revision, completed session, unavailable shared radar or automatic picker, products-only asset); `413` body too large; `500` the server could not write files.
- **Responses never contain server paths.**

## Shared radar

| Method | Path | Purpose |
|---|---|---|
| GET | `radar/sources` | Shared radar sources of this installation. |

Response: `{"sources": [{"key", "title", "status", "flight", "cbd_start", "cbd_end", "dataset_id", "observation_tiff", "has_nav", "filename"}]}`.

## Radar assets

| Method | Path | Purpose |
|---|---|---|
| GET | `assets` | The user's assets, newest first. |
| POST | `assets/shared` | Reference a shared source: `{"source": "<key>"}`. Returns the existing asset if already referenced. `201`. |
| POST | `assets/upload` | Upload raw radar: multipart `tiff` (required, `.tif`/`.tiff`, ≤ 200 MB) and `nav` (optional CSV). `201`. |
| POST | `assets/products` | New products-only asset: multipart `kind`, `file` (optional `title`). `201`. |
| GET | `assets/<asset_id>` | Asset detail plus `nav_rows` (exact navigation records in the CBD range). |
| DELETE | `assets/<asset_id>` | Remove the asset from the user's workspace (`409` while automatic picking runs). Shared radar itself is never touched. |
| GET | `assets/<asset_id>/view?x=&width=&scale=` | PNG of source columns `[x, x+width)` at integer `scale` ∈ {1,2,4,8,16,32,64}, full height, ≤ 6 Mpx. |

An asset object: `{"asset_id", "origin" ("upload" | "shared" | "products"), "title", "filename", "flight", "cbd_start", "cbd_end", "image" ({"format", "mode", "width", "height", "compression", "bytes"} or null), "nav" ({"present", "rows", "cbd_min", "cbd_max", "positions", ...}), "created_at", "available", "shared_source"?, "status"?}`.

## Manual picking (ASTRA)

| Method | Path | Purpose |
|---|---|---|
| GET | `assets/<asset_id>/manual` | Session (status `new` until the first action), ASTRA geometry, title, state, current picks, trace of the current window, committed rows as in the CSV, outputs. |
| POST | `assets/<asset_id>/manual` | One action (≤ 16 KB JSON), applied under a per-asset lock. |
| GET | `assets/<asset_id>/manual/window?slider=` | The smoothed ASTRA working window (2300 columns of rows 250–1800) as PNG, at half resolution for display. |
| GET | `assets/<asset_id>/outputs/astra-csv`, `.../astra-qc` | ASTRA outputs (equivalent to the product download). |

Action bodies (all include `"revision": <current revision>`; a stale revision answers `409`):

| `action` | Fields |
|---|---|
| `setup` | `target`: `x_reference`, `y_reference`, `y_axis`, `x_axis` |
| `sweep_rate` | `rate`: 1, 2, 5 |
| `select` | `feature`: `Surface`, `No Surface`, `Bed`, `No Bed`, `Noise Floor`, `Main Bang` |
| `click` | `x`, `y`: matplotlib data coordinates in the working window (`-0.5 ≤ x < 2299.5`, `-0.5 ≤ y < zoom_height - 0.5`) |
| `move` | `slider`: integer in `[0, slider_max]` |
| `step` | `step`: `left` (−10), `right` (+10), `jump` (+1000) |
| `suggest`, `next`, `done` | — |
| `reset` | `confirm: true` (no revision needed); removes the session and ASTRA outputs, keeps the radar |

An unreadable or tampered `session.json` answers `409 {"error", "session_invalid": true}`; `reset` recovers it.

## Automatic picking (URSA)

| Method | Path | Purpose |
|---|---|---|
| GET | `assets/<asset_id>/automatic` | `{"availability": {"available", "picker", "reason", "environment"}, "has_radar", "job", "warnings", "products", "scientific_status", "scientific_note", "publication_eligible"}`. `availability.environment` (when available) is `{"python", "packages": {"numpy", "scipy", "pandas", "matplotlib", "cv2", "skimage"}}` -- versions from the health check, never paths. `scientific_status` is always `"unvalidated"` and `publication_eligible` always `false`; `job.scientific_status` is `"unvalidated"`. A completed job has `job.provenance` (URSA commit if determinable, source/config SHA-256, parameters, input/output and diagnostic-image hashes; no paths). `products` lists the results; `ursa-diagnostic` images are not in it but in `frames`: `{"columns", "rows": [{"frame", "values", "flags", "images": [{"product_id", "title", "label", "bytes", "sha256", "preview_url", "download_url"}]}], "flagged", "diagnostic_images", "label", "note", "scientific_status", "truncated"}` (or `null` without an automatic result). `values` are URSA's CSV text as written; `flags` are heuristic and correct nothing. |
| POST | `assets/<asset_id>/automatic` | `{"action": "start"}` (`409` if unavailable, already running, or no raw radar) or `{"action": "cancel"}`. |

A job: `{"job_id", "picker", "status" (queued, running, completed, failed, cancelled, interrupted), "created_at", "started_at", "finished_at", "message", "log_tail", "summary", "warnings"}`.

## Products and downloads

| Method | Path | Purpose |
|---|---|---|
| GET | `assets/<asset_id>/products` | `{"products": [...], "upload_kinds": [{"kind", "title", "extensions"}]}`. |
| POST | `assets/<asset_id>/products` | Upload a processed product: multipart `kind` then `file` (optional `title`). `201` with the updated list. |
| GET | `assets/<asset_id>/products/<product_id>` | Download (`Content-Disposition: attachment`). `403` for products that are listed but not downloadable (shared radar). |
| GET | `assets/<asset_id>/products/<product_id>/preview` | PNG preview of an image product (≤ 2400 × 1200). |
| DELETE | `assets/<asset_id>/products/<product_id>` | Remove a user-uploaded product (`403` otherwise). |
| GET | `assets/<asset_id>/products.zip` | The downloadable products (not the raw TIFF) plus `PRODUCTS.json`. |

A product: `{"product_id", "asset_id", "kind", "title", "type", "producer" ("frozen-legacies" | "user"), "workflow" ("astra-manual" | "ursa-automatic" | "upload" | "radar-source"), "filename", "mime", "bytes", "created_at", "available", "downloadable", "previewable", "provenance", "summary", "download_url", "preview_url"}`. URSA products (workflow `ursa-automatic` or an `ursa-*` kind) also carry `"scientific_status": "unvalidated"`.

Upload kinds: `navigation`, `astra-csv`, `astra-qc`, `ursa-csv`, `lyra-echoes-csv`, `echogram`, `radargram`.

## Radar catalog

| Method | Path | Purpose |
|---|---|---|
| GET | `radar/catalog?dataset=&flight=&status=&state=&q=&cbd=&id=&page=&page_size=` | Server-side search of the installation's radar catalog. `page_size` ≤ 100. `status` is the index status (`indexed`, `changed`, `missing`, `invalid`, `unavailable`; default: available files). `state` is the signed-in user's processing or review state (`unprocessed`, `manual_in_progress`, `manual_completed`, `automatic_pending`, `automatic_running`, `automatic_completed`, `automatic_failed`, `needs_review`, `returned`, `published`). `q` matches the file name literally; `id` looks up one catalog ID. |
| GET | `radar/catalog/summary?dataset=` | Datasets and flights with file counts, CBD ranges and navigation coverage; each flight has `published` and `awaiting_review` (catalog files with a published / pending result, all users) and `mine`: the user's progress (`unprocessed`, `manual_in_progress`, `manual_completed`, `automatic_*`, `needs_review`, `returned`, `published`). |
| GET | `radar/catalog/segments?dataset=&flight=&bbox=&limit=` | Catalog files with real navigation tracks as GeoJSON (LineString/Point), `limit` ≤ 5,000. Files without navigation are not included; `summary` is `{"returned", "truncated", "unplaced"}`, where `unplaced` counts the matching files that have no navigation and therefore no position. |

A catalog item: `{"catalog_id", "source_id", "source_name", "dataset_id", "filename", "flight", "cbd_start", "cbd_end", "width", "height", "mode", "bytes", "has_nav", "status", "duplicate", "first_indexed_at", "indexed_at", "processing"}`. Storage keys and locations are never returned. Open a catalog file with `POST assets/shared` and `{"source": "<catalog_id>"}`: the file is referenced, not copied.

## My observations

| Method | Path | Purpose |
|---|---|---|
| GET | `observations?bbox=&status=&asset=&limit=` | The signed-in user's picked observations as a GeoJSON FeatureCollection (WGS84). `bbox` is `min_lon,min_lat,max_lon,max_lat`; `status` is `draft` or `completed`; `limit` ≤ 20,000. `summary` reports counts and observations without a mappable position. |

Each feature is one row of the asset's ASTRA CSV (same CBD, LAT/LON and values) with `workflow`, `status`, pick provenance and the georeferencing fields; its geometry is the verified position when the CBD was confirmed against the film, none when the label was unreadable, otherwise ASTRA's position (`geolocation_status` says which). Only the owner can read them; they are never added to the shared dataset files. With a catalog database the response comes from an indexed, owner-scoped copy of the workspace's `observations.json` files.

## Review and publication

Owners (their own assets):

| Method | Path | Purpose |
|---|---|---|
| GET | `assets/<asset_id>/review` | `{"can_submit", "reason", "submissions": [...]}` for the asset, newest first. |
| POST | `assets/<asset_id>/review` | `{"action": "submit", "note"?}` freezes a snapshot of the completed result (`201`; `409` if not completed, not on shared radar, already awaiting review, or this version is already published). `{"action": "cancel", "submission_id"}` cancels a pending submission. |
| GET | `reviews/mine` | The user's submissions. |

A submission: `{"submission_id", "asset_id", "catalog_id", "dataset_id", "filename", "flight", "cbd_start", "cbd_end", "workflow", "producer", "producer_version", "session_revision", "source_version", "navigation", "observation_count", "positioned_count", "products": {"astra-csv"|"astra-qc": {"name", "bytes", "sha256"}}, "note", "status", "submitted_at", "decided_at", "decision_note", "accepted_unverified", "published_at", "supersedes", "superseded_by", "withdrawn_at", "withdraw_reason"}`. `status` is `submitted`, `returned`, `rejected`, `published`, `withdrawn`, `superseded` or `cancelled`.

Everyone signed in (the shared, reviewed product):

| Method | Path | Purpose |
|---|---|---|
| GET | `published/observations?dataset=&flight=&bbox=&limit=` | Published observations as GeoJSON, `limit` ≤ 5,000. Properties: scientific values, `cbd` (verified when verified), `astra_cbd`, `astra_position`, `geolocation_status`, `geolocation_acceptance`, dataset, catalog ID, file name, flight, producer and version, `submission_id`, `published_at`. No account information. |
| GET | `published/<submission_id>/products/<astra-csv\|astra-qc\|provenance>` | Downloads of a published result; `404` for anything not currently published. |

Reviewers (Control Center `maintainer`, `admin`, `owner`; `403` otherwise):

| Method | Path | Purpose |
|---|---|---|
| GET | `admin/reviews?status=&page=` | The queue (pending first) with counts per status; `own` marks the reviewer's own submissions. |
| GET | `admin/reviews/<submission_id>` | Snapshot detail: `submission` (with submitter/reviewer account IDs), `integrity` (`ok`, `problems`, `files`: every snapshot file checked against `SNAPSHOT.json`), `observations`, `provenance`, `geolocation` (`verified`, `message`), and `supersedes_on_approval` when approving would supersede a published version (`submission_id`, `observation_count`, `verified_count`, `published_at`). A missing or damaged snapshot is reported in `integrity` with empty `observations`. |
| GET | `admin/reviews/<submission_id>/products/<astra-csv\|astra-qc\|provenance>` | The snapshot's files. |
| POST | `admin/reviews/<submission_id>/decision` | `{"decision": "approve" \| "return" \| "reject", "note"?, "accept_unverified_geolocation"?}`. `return`/`reject` need a `note`; approving unverified positions needs `accept_unverified_geolocation: true` (`409` otherwise); deciding one's own submission is `403`; a submission not awaiting review, or approving a damaged or incomplete snapshot, is `409`. |
| POST | `admin/reviews/<submission_id>/withdraw` | `{"reason"}`: removes a published result from the shared product. |

## Georeferencing

Owner-scoped: other users get `404`. `POST` is refused from another origin (`403`). See the Developer Guide, *CBD provenance and georeferencing*.

| Method | Path | Purpose |
|---|---|---|
| GET | `assets/<asset_id>/georef` | Every committed A-scope with `astra_cbd`, `astra_position`, `film_cbd`, `verified_cbd`, `verified_position`, `cbd_source`, `georef_method`, `geolocation_status` and `cbd_differs`, plus `summary` counts, plausibility `warnings`, `publication` (`ok`, `reason`: whether every observation is verified) and the product links. |
| POST | `assets/<asset_id>/georef` | `{"action": "confirm", "a_scope", "film_cbd"}` (the CBD read from the frame label, a whole number 0--99999), `{"action": "unreadable", "a_scope", "note"?}` or `{"action": "clear", "a_scope"}`. Returns the updated state. `409` before A-scopes are committed; `400` for an invalid value or an A-scope that is not committed. |
| GET | `assets/<asset_id>/georef/product` | `<stem>_georef.csv`: ASTRA's and the verified CBD and position per A-scope (deterministic). |
| GET | `assets/<asset_id>/georef/provenance` | How the georeferenced CSV was made: hashes of the product, the ASTRA CSV, the navigation and the confirmations; asset, catalog file, dataset, session revision. |

The canonical ASTRA products are never changed by georeferencing.

## Data sources (maintainers)

These require a Control Center role of `maintainer`, `admin`, or `owner`, checked against the role store on every request (`403` otherwise). A source in the listing has `location` (masked; `s3://bucket/prefix` for S3, with `region` and `endpoint` name), `connection` (last test), `counts` (indexed, invalid, unavailable, missing, moved, duplicates, processed), `last_success_at`, `last_index_at`/`status`/`error`, `indexing` and `progress` (the active run: status, counts so far, `heartbeat_at`, `cancel_requested`, `known_total`), recent `runs`, and `recent_errors` (file name, status, message); never credentials, storage keys or endpoint URLs.

| Method | Path | Purpose |
|---|---|---|
| GET | `admin/sources` | Data sources with index counts and recent index runs. |
| POST | `admin/sources` | Register a source: `{"source_id", "name", "dataset_id", "provider": "local", "root", "tiff_prefix"?, "nav_template"?}` (the root must be inside an approved storage root) or `{"source_id", "name", "dataset_id", "provider": "s3", "bucket", "prefix"?, "region"?, "endpoint"?, "tiff_prefix"?, "nav_template"?}` (the bucket/prefix must be approved in `CRYOSTACK_FROZEN_LEGACIES_S3_ALLOWED`; `endpoint` names an entry of `CRYOSTACK_FROZEN_LEGACIES_S3_ENDPOINTS`). Any credential-like field is refused (`400`). `201`. |
| POST | `admin/sources/<source_id>/test` | Connection test, recorded on the source: `{"ok", "message"}`. |
| POST | `admin/sources/<source_id>/index` | Queue a background index run (a separate worker process): `{"full": true}` re-reads unchanged files; `{"allow_mass_missing": true}` confirms removals after a `needs_confirmation` run. `202` with `run_id`; `409` if the source already has an active run or is disabled. |
| POST | `admin/sources/<source_id>/retry` | Queue an incremental run that also re-reads files recorded as `invalid` (`unavailable` files are re-read by every run). `202`; `409` as above. |
| POST | `admin/sources/<source_id>/cancel` | Stop the active run: a queued run ends at once, a running one after its current batch (`cancelled`; indexed files kept, nothing marked missing). `202`; `409` if nothing is running. |
| POST | `admin/sources/<source_id>/status` | `{"status": "enabled" | "disabled"}`. |

The Control Center page `/control/frozen-legacies` uses these endpoints.

## Shared dataset downloads

| Method | Path | Purpose |
|---|---|---|

## Python modules

| Module | Responsibility |
|---|---|
| `server.py` | Route installation (`install_frozen_legacies`), authentication wrapper, request validation, error mapping. |
| `workspace.py` | `FrozenLegaciesWorkspace`: per-user root, asset IDs, path containment. |
| `radar/ingest.py` | TIFF and navigation validation; ASTRA's filename parser. |
| `radar/sources.py` | Shared radar registry. |
| `radar/assets.py` | `asset.json`; upload/shared/products assets; resolving an asset's files. |
| `radar/render.py` | Decoded-image cache and server-side window rendering. |
| `radar/manual.py` | ASTRA session documents, validation, atomic outputs, working-window cache. |
| `radar/automatic.py` | URSA availability and subprocess jobs. |
| `radar/products.py` | Product model, upload validation, summaries. |
| `radar/storage.py` | Storage-provider interface; local/mounted and read-only S3 providers; storage-key safety and S3 approvals. |
| `radar/catalog.py` | SQLite radar catalog: data sources, radar files, index runs, per-user state; search, summaries, segments. |
| `radar/working_cache.py` | Bounded working copies of data-source objects for the pickers. |
| `radar/indexer.py` | Incremental indexing of a data source into the catalog (progress, cancellation, parallel remote header reads). |
| `radar/index_worker.py` | Background indexing worker process: claims a queued run, heartbeat, progress, cancellation. |
| `radar/observations.py` | Structured observations from ASTRA sessions (the user's live map layer). |
| `radar/georef.py` | CBD provenance and georeferencing: confirmed film-frame CBDs, verified positions, the georeferenced CSV and its provenance. |
| `georef_routes.py` | Georeferencing routes (owner-scoped). |
| `catalog_routes.py` | Catalog, observation and data-source routes; the Control Center page. |
| `radar/review.py` | Submissions, immutable snapshots, review decisions, publication, supersession and withdrawal. |
| `review_routes.py` | Review and publication routes; the Control Center review page. |
| `pickers/astra.py` | ASTRA port (parity-tested against `Pickers/ASTRA_MAC.py`). |
| `pickers/ursa_runner.py` | URSA entry point run in a subprocess. |
