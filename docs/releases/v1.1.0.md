# CryoStack v1.1.0

CryoStack v1.1.0 captures the current scientific application, computing,
operations, and storage developments since v1.0.1.

## Highlights

- Expanded Control Center views for compute, access, audit, operations,
  analytics, settings, and experiment records, including mobile layouts.
- Authentication and kernel-isolation improvements, backup verification and
  recovery tooling, and stronger workspace-isolation tests.
- Frozen Legacies catalog, radar, georeferencing, product, and picker
  interfaces, with CEDAR immutable-dataset integration and local-XFS mutable
  intake configuration and preflight checks.
- LIVIST application integration for products, jobs, validation, and
  publication dry runs.
- ICESEE example discovery, private example staging, remote status polling,
  run monitoring, user-editable plotting copies, and revised cloud staging.
- Vendored ICESEE source updates for distributed execution, resource planning,
  checkpoints, postprocessing, model adapters, and execution-mode tests.
- Configuration-agent refinements, refreshed application documentation, and
  manuscript build workflow updates.

## Scope and limitations

This source release does not deploy, restart, migrate, or reconfigure the
running service. Storage backup/recovery acceptance, authenticated staging
browser/access checks, and representative multi-rank cloud/runtime
qualification remain outstanding as recorded in the operational handoffs.
Do not interpret source publication as production-readiness certification.

Mutable workspaces, databases, and resumable intake state belong on local
durable storage; CEDAR/SMB is reserved for immutable dataset releases. Review
the storage runbooks and preflight requirements before deployment.

RIGGS products remain provisional and citation-pending; automatic picker
outputs remain scientifically unvalidated and publication-ineligible.
Downloaded archives, local/generated scientific data, compiled executables,
and backup files are excluded from this source snapshot and preserved on the
server. Application submodules retain their recorded revisions.

The JOSS submission branch and its selected v1.0.0 snapshot are unchanged.
