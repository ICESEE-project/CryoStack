% --- Figure rendering -------------------------------------------------------
% paper.md writes each figure as a standalone Pandoc image with an identifier
% attribute, e.g.:
%   ![<long caption text>](cryostack_architecture.svg){#fig:architecture}
% The markdown package's own built-in image renderer treats the *title*
% (the optional quoted string after the URL) as the figure caption, but
% paper.md follows Pandoc's implicit-figures convention of putting the
% caption in the image's alt text instead, and paper.md never gains a title
% string just to satisfy that default. So the built-in renderer is replaced
% below with one that (a) takes the caption from the alt text (renderer
% argument #1) and (b) takes the image path from the raw URI (argument #3),
% while still relying on paper.md as the sole source of both strings.
%
% \markdownRendererImage receives 4 arguments: #1 = alt text (the caption
% text as written in paper.md), #2 = escaped URI, #3 = raw URI (the image
% path), #4 = optional quoted title (unused here, always empty in paper.md).
%
% The identifier from `{#fig:...}` arrives separately: imageAttributeContext
% Begin/End bracket each image that carries attributes, and attributeIdentifier
% fires in between with the identifier text. That value is captured into
% \wrapperFigLabel so the image renderer can turn it into a \label{...}.
\newcommand{\wrapperFigLabel}{}
\newcommand{\wrapperFigLabelEmpty}{}
\markdownSetup{
  renderers = {
    imageAttributeContextBegin = {\begingroup\def\wrapperFigLabel{}},
    attributeIdentifier        = {\def\wrapperFigLabel{#1}},
    imageAttributeContextEnd   = {\endgroup},
    image = {%
      \begin{figure}[htbp]
        \centering
        \includegraphics{#3}
        \caption{#1}
        \ifx\wrapperFigLabel\wrapperFigLabelEmpty\else
          \label{\wrapperFigLabel}%
        \fi
      \end{figure}
    },
  },
}
